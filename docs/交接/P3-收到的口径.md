## 1. `Result` 的四个坑（必须按右列口径展示）

| 字段 | 坑 | 界面 / 报告怎么写 |
| --- | --- | --- |
| `transfers`（Dijkstra / A\*） | 值是"**沿它自己那条路径**的最少线路切换（DP 求得）"，**不是**全局最少换乘 | 标签写「本路径换乘次数」；不要写「最少换乘」 |
| `transfers` + `distance_km` / `time_min`（BFS） | BFS 只优化换乘，**距离/时间是附带值**，不是最优距离/时间 | 对比表 BFS 行加注「目标：最少换乘；距离/时间为该路径附带值」 |
| `expanded` | BFS 的单位是 **状态**（站点 × 线路），另外两个是**站点** | 表注必须写；否则会被读成「BFS 扩展更多、更慢」 |
| `elapsed_ms` | 算法内部**单次** `perf_counter`，微秒级抖动 50%+ | 界面可显示（保留 2 位小数），**报告数字改用 `tools/bench*_summary.csv` 的中位数** |
| `events` | 只有 `("settle", sid)`，且因提前 `break` **不包含所有节点** | 只喂动画，别当「访问了哪些站」的证据 |

```python
# 正确读法
r = solver.solve(g, s, t, algo, weight)   # Result
r.path          # 站点 id 序列（可直接映射成站名清单）
r.transfers     # 见上表：A*/Dijkstra = 本路径切换数；BFS = 最小换乘
r.expanded      # 单位随算法变化
r.events        # 仅动画用
```

## 2. 异常必须分两路

| 异常 | 何时抛 | 界面动作 |
| --- | --- | --- |
| `solver.PathNotFound` | 两站不连通 / 起点没有任何线路 | 弹窗「不连通」+ 提示换起终点（任务书明确要求展示这种异常处理） |
| `core.graph.DataError` | 未知站点、未知权重、未知算法、数据文件坏 | 弹窗「数据错误」+ 日志留痕，**不要静默** |

另：`solve(g, s, t, "bfs")` **忽略 weight**（BFS 没有权重概念）⇒ 选中 BFS 时把权重下拉置灰，避免用户以为可选。

## 3. 动画与结果必须逐项一致

同一对起终点，「动画演示」与「立即求解」的数值必须相等。P2 只保证算法结果；播放顺序由 P4 的渲染器负责。
**不要在搜索循环里 `sleep`**——先算完，再播 `events`。

## 4. 三算法对比表怎么摆

- Dijkstra 与 A\* 必须**同一 weight** 才可比；BFS 行单独标注目标不同。
- 数值来源二选一：现场调 `solver.solve()` 三次，或读 `tools/bench_summary.csv`；**禁止手抄**（手抄必漂移）。
- 推荐列：`算法 | 目标 | 距离 km | 时间 min | 换乘 | 扩展 | 耗时 ms`，其中「目标」列写「最短/最快/最少换乘」。

## 5. 性能观感

240 站时三算法都在 `0.12–0.26 ms` 级（Dijkstra 0.1466 / A\* 0.1244 / BFS 0.2630）。
界面卡不卡取决于渲染与动画节奏，**不取决于算法** ⇒ 不要为了「更快」去改 A\* 的 `h` 或裁剪搜索，那会破坏最优性。

## 6. 只用公共 API

可用：`dijkstra / astar / bfs_transfers / solve / analyze_path / Result`。
不要用：`_heuristic`、`_vmax`、`_check`（私有实现，P2 以后可能改）。
