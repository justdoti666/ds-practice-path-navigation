## 1. 通用口径（四个人都适用）

1. **契约只加不改**：改 `core/*` 的签名/字段 → 在 `docs/契约变更.md` 记一条 + bump `core/__init__.py` 的 `CONTRACT_VERSION` + 通知全组。当前 `1.1.0`（新增 `astar(heuristic=...)`，其余签名不变）。
2. **合并前闸门顺序**：`python main.py --check` → `python -m unittest discover -s tests -t .` → `python tools/bench.py --check-cv 15` → UI 截图。任一红灯不许合并。
3. **计时口径**：报告里的毫秒数**只能**来自 `tools/bench.py`（批量计时 + 7 轮中位数 + CV 闸门，本次 CV 中位 8.25%）；`Result.elapsed_ms` 是单次 perf_counter 观测，微秒级抖动可达 50%+，不能进对比表。
4. **三条禁止**：界面层写最短路算法 / 算法层 import tkinter / 手抄 bench 数字进报告。

## 2. 给 P1（数据与图模型）

### 2.1 【请求】边权存全精度，显示层再取整

- **现状**：`core/graph.py::_add_edge` 把 `distance_km` 取整到 3 位、`time_min` 取整到 2 位。
- **证据**：实测 `S10→S11`，几何下界 `h=3.0233`，而存储后的最优代价 `3.02` ⇒ `h` **微小高估 0.11%**（每边向下误差 ≤0.005 min）。
- **影响**：A* 的可采纳性从"严格成立"降为"≤0.5% 容差成立"；目前 180 个（点对×权重）代价仍与 Dijkstra 完全一致（单测 T03/T04），但这是**运气好**，不是证明。
- **请求动作**：`_add_edge` 里去掉 `round()`，只在 `Result`（展示层）保留 2/3 位。
- **收益**：P2 的严格断言 T14a 可直接覆盖全部图，T14b 容差断言可删除；报告里"可采纳性"这节不用加补丁说明。

### 2.2 【请求】加载阶段校验几何自洽：`time_min ≥ distance_km / v_max × 60`

- **现状**：只校验 `time_min > 0`，不校验与速度是否自洽。
- **后果**：若显式给的 `time_min` 小于该下界，A* 会**高估**、可能给出非最优路径，而单点测试常常发现不了。
- **请求动作**：加载时若 `time_min < distance_km / v_max × 60 - 1e-9`，抛 `DataError`（或至少 `warnings.warn` 并在 `meta` 标记）。

### 2.3 【保持】已冻结的图接口（P2/P3/P4 都在用）

```python
Graph.stations: dict[str, Station]        # Station(sid, name, x, y)，坐标单位 km
Graph.lines: dict[str, {name, speed_kmh, color}]
Graph.edges: list[Edge]                   # Edge(u, v, line, distance_km, time_min)
Graph.neighbors(sid) / edge_between(u, v) / lines_of_station() / bbox() / path_metrics()
Graph.validate()
```

改字段名/返回类型属于破坏性变更：先记 `docs/契约变更.md`，再改，再 bump。

### 2.4 【建议】动态增删（P1-06）的口径

- `remove_station(sid)`：**级联删边**（并返回被删边数），否则 `adj` 里会留悬空边、`lines_of_station()` 会统计到幽灵线路。
- 增删后**必须重算 `adj`**；`validate()` 要能被反复调用（幂等）。
- 建议在 `meta` 里加 `mutation_log`（可选），便于报告写"支持动态增删"时给证据。

## 3. 给 P3（界面与交互）

### 3.1 `Result` 字段的四个"坑"

| 字段 | 坑 | 界面/报告怎么写 |
| --- | --- | --- |
| `transfers` | Dijkstra/A\* 的值是"**沿它自己那条路径**的最少线路切换（DP 求得）"，不是全局最少换乘 | 标签写"本路径换乘次数"；BFS 行写"最少换乘" |
| `transfers`（BFS） | 只有 BFS 的 `distance_km/time_min` 是**该路径的附带值**，不是最优距离/时间 | 对比表加注"BFS 只优化换乘" |
| `expanded` | BFS 的单位是**状态**（站点×线路），另外两个是**站点** | 表注必须写，否则会被读成"BFS 更慢" |
| `elapsed_ms` | 单次测量，微秒级抖动 50%+ | 界面可显示 2 位小数；**报告数字改用 bench 中位数** |
| `events` | 只有 `("settle", sid)`，且因提前 `break` **不包含所有节点** | 只用来做动画，别拿它当"访问了哪些站"的证据 |

### 3.2 异常契约（必须分开处理）

- `solver.PathNotFound`：两站不连通 / 起点没有任何线路 → 弹窗提示换起终点（任务书要求展示这种异常）。
- `core.graph.DataError`：未知站点、未知权重、未知算法、数据文件坏 → 提示"数据错误"，不要静默。
- `solve(g, s, t, "bfs")` **忽略 weight**（BFS 没有权重概念）：选 BFS 时把权重下拉框置灰，避免用户以为可选。

### 3.3 动画与结果必须一致

同一对起终点，"动画演示"与"立即求解"的数值必须逐项相等（P2 只保证算法结果；播放顺序由 P4 的 `CanvasView` 负责）。
**不要在搜索循环里 `sleep`**——先算完再播事件。

### 3.4 三算法对比表怎么摆

- Dijkstra 与 A\* 必须**同一 weight** 才可比；BFS 行要单独标注"目标：最少换乘"。
- 建议对比表数值直接现场调用 `solver.solve()` 三次，或读 `tools/bench_summary.csv`，**禁止手抄**（手抄必漂移）。

### 3.5 性能观感

240 站时三算法都在 `0.12–0.26 ms` 级，界面卡不卡取决于渲染/动画，不取决于算法。别为了"更快"改算法口径（如把 A\* 的 `h` 放大），那会破坏最优性。

### 3.6 只用公共 API

`dijkstra / astar / bfs_transfers / solve / analyze_path / Result`；`_heuristic`、`_vmax`、`_check` 是私有实现，界面别调（P2 以后可能改）。

## 4. 给 P4（渲染与工程化）

### 4.1 两套测试是**有意重复**的，别合并

| 套件 | 归属 | 用途 |
| --- | --- | --- |
| `selfcheck.py`（10 组断言，`--check`） | P4 | 端到端闸门（数据/算法/边界/渲染冒烟），面向"整个程序能不能交付" |
| `tests/`（18 条单测） | P2 | 算法层细粒度回归（全点对、属性测试、红绿判别） |

两者各有一套独立 oracle（`selfcheck.brute_min_transfers` 与 `tests/support.brute_min_transfers` 各写一份）。**不要为了去重删掉其中一套**——独立实现互相印证才是目的。

### 4.2 闸门顺序（合并前）

```powershell
python main.py --check                                  # P4
python -m unittest discover -s tests -t .               # P2（18 条）
python tools/bench.py --check-cv 15                     # P2（噪声闸门）
python tools/make_figs.py --out docs/figs                # P2（改图后才跑）
```

### 4.3 报告数字的来源

- 扩展数/耗时：`tools/bench_summary.csv`、`tools/bench_scale_summary.csv`
- 手工对照：`docs/bench.md` §3
- 复杂度：`docs/bench.md` §2（推导）与 `docs/技术方案.md` §4.4
- 图 4-1（扩展数柱状图）：由 `tools/bench_summary.csv` 生成，**换了 bench 数据要重跑 `make_figs.py`**，否则图与表对不上。

### 4.4 插图维护

`docs/figs/*.png` 由 `tools/make_figs.py` 生成，脚本内含像素自检（非白像素比例断言）。改配色/字号时保留 `--out` 参数与自检；若重画，请同步更新报告图注里的"图 3-1/3-2/3-3"编号。

### 4.5 事件是动画的唯一入口

用 `Result.events`（settle 序列）做逐帧上色，**不要**在渲染层另算搜索过程（会出现"动画与结果不一致"）。切换算法前记得 `after_cancel` 旧动画并清画布。

### 4.6 `selfcheck.py` 的两条"守门人"断言，只可加不可删

1. A\* 与 Dijkstra **全点对同代价**（可采纳性 ⇒ 最优性）；
2. BFS 换乘数 = **暴力枚举**最小值。

删掉这两条，等于放弃发现"h 写错/换乘建模错"这类最贵的 bug。
