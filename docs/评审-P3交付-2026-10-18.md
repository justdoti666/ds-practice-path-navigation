## 3. 与真实仓库的 4 类不兼容（不能直接 merge 的原因）

| # | P3 假设 | 我们的真实实现 | 影响 |
| --- | --- | --- | --- |
| 1 | `from core.graph import Graph, **GraphDataError**, load_graph`；`load_graph(DATA_DIR)` 读 `data/*.csv` | `core.graph` 导出 **`DataError`**、`load_graph(file)` 读 JSON/TXT | `window.py:28` 直接 **ImportError**；数据结构也对不上（20 站 CSV vs 169 站 JSON） |
| 2 | `graph.iter_edges()`（window.py:834）、`graph.edge_between(u,v)` **返回单条边**（1173）、`graph.is_empty`（311） | 没有 `iter_edges`/`is_empty`；`edge_between` 返回**列表**（平行线路） | 调用处 AttributeError；`edge.line` 对 list 报错 |
| 3 | `view.show_selection(start,end)`（945/1010/1143）、`view.animate(..., on_done=cb)`（1256）、`view.animation_duration_ms(...)`（1260，有 hasattr 兜底） | P4 canvas 有 `bind_click/reset/show_path/animate/set_graph/refresh`，**没有** `show_selection`、`on_done`、`animation_duration_ms` | 前两个会直接 TypeError/AttributeError；时长有降级不影响 |
| 4 | 契约桩 `Result.events: list[dict]`；P3 自带 canvas 按 dict 解析 | P2 的 `events` 是 `(kind, sid)` 元组；P4 canvas 已兼容元组 | 换 P4 canvas 后无问题；若保留 P3 桩 canvas，动画会解析失败 |

另：P3 的 `bench.csv`/`data/*.csv` 来自它自己的 solver 桩，合入后必须以我们的 `tools/bench.py` + `data/*.json` 为准，不能两份数据并存。

## 4. 建议的整合方案

**推荐 A（P3 自己做，保留署名与测试）**：从 `main@965e2c7` 拉分支，把 P3 副本的 `ui/window.py`、`ui/widgets.py`、`tests/test_ui.py`、截图与第 4 章草稿搬过来，然后加一层 ~150 行适配：

1. `ui/p3_compat.py`：`GraphView` 提供 `iter_edges()/is_empty/edge_between()->单条(取 time 最小)/bbox`；`load_graph` 包装我们的 JSON/TXT 加载器；`DataError` 别名 `GraphDataError`。
2. 画布：直接用 P4 的 `CanvasView`，包一层 `P4CanvasAdapter` 补 `show_selection()`（画起/终标记）、`animate(..., on_done=)`（按 `animation_duration_ms` 在结束后回调）；`animation_duration_ms` 由 `events` 长度估算。
3. 数据：`main.py` 默认加载 `data/demo_city.json`，真实规模用 `data/real_metro.json`；`--data` 传文件而非目录。
4. 测试：18 条用例的假 solver 形状与我们的 `Result` 兼容（只差 `events` 类型，测试里没消费），把 fake graph 换成 `GraphView` 即可；再补 2–3 条"P4 canvas 适配"用例。

**方案 B（我们代做）**：同样步骤，我们出一版可运行分支，P3 复核署名。工作量约 **半天**，主要花在窗口里 3 处 Graph API 与 3 处 canvas 调用的胶水，以及 169 站性能/标签密度验证。
