# 契约变更记录（P2 · 2026-10-17）

> 规则来源：《技术方案》§6.5 —— **只加不改**，破坏性变更必须 bump 主版本并全组同步。
> 当前 `core.CONTRACT_VERSION = "1.1.0"`。

## [1.1.0] 2026-10-17 · P2 新增可选 `heuristic` 参数（向后兼容）

| 项 | 变更 | 影响面 | 兼容性 |
| --- | --- | --- | --- |
| `astar(g, start, goal, weight="time", heuristic=None)` | 新增可选参数，签名 `heuristic(g, sid, goal) -> float` | P3/P4 走 `solve()`，不受影响 | ✅ 向后兼容（默认 None 用内置 h） |
| `core.CONTRACT_VERSION` | 新增常量 `"1.1.0"` | 全组可见 | ✅ 纯新增 |
| `bfs_transfers` 内部 | 增加 `processed` 集合（0-1 BFS 标准去重） | 只影响 `expanded` 数字（变准），不改语义 | ✅ 结果不变 |
| `_heuristic(...)` | 增加可选 `vmax` 形参（A* 每次求解只算一次最大速度） | 私有函数 | ✅ 内部 |

**变更理由**：报告需要"曼哈顿 vs 欧几里得"的对比实验；单测需要注入**非可采纳** h 来证明测试有判别力（T15）。
用参数注入比 monkeypatch 干净，且不改 `Result`、不改 `solve()`、不改异常类型。

**验证**：`python main.py --check` 仍 ALL PASS；`python -m unittest discover -s tests -t .` 18 条全过。

## 待 P1 决策（数据精度，会影响"可采纳性"的严格性）

| 现象 | 证据 | 建议 |
| --- | --- | --- |
| 加载器把 `time_min` / `distance_km` 取整到 2/3 位小数，**向下误差 ≤0.005/边**，导致几何启发式可能出现 ≤0.5% 的微小高估 | 单测 T14b；实测 `S10→S11`：`h=3.0233` vs 存储最优 `3.02` | **存储保留全精度，显示层（`Result`）再取整**。这样 `h ≤ 真实代价` 严格成立，报告里的可采纳性证明不用加"取整容差"补丁 |
| 影响 | 目前 A\* 与 Dijkstra 在 180 个（点对×权重）上代价仍完全一致（T03/T04），但严格性上留了一个小口子 | 若 P1 同意，改动只在 `core/graph.py` 的 `_add_edge` 两行（P1 的文件，P2 不越界改） |

## [1.2.0] 2026-10-18 · Result 增加 `lines` + 三项健壮性修复

| 项 | 变更 | 影响面 | 兼容性 |
| --- | --- | --- | --- |
| `Result.lines` | 新增字段：每跳所用线路序列（`len(path)-1`） | P3 画线/标注应改用它；P4 只在统稿说明里提 | ✅ 纯新增 |
| `core/graph.validate()` | 新增**站名查重**（重名抛 `DataError`） | P1 数据加载；`main.resolve` 歧义不再静默 | ⚠️ 以前能加载的重名数据现在会被拒 |
| `solver.bfs_transfers` | 不再校验无关的 `weight`（改用 `_check_stations`） | 无行为变化 | ✅ |
| `Graph.path_metrics()` | 同站换乘段按 0 距离/0 时间跳过（不再抛异常） | 展示层累计 | ✅ |
| `main.resolve()` | 同名站点命中多个时**报歧义**并列出候选 id | CLI/界面选点 | ⚠️ 重名数据会得到明确错误 |

**验证**：单测 19→**23**（T19 lines、T20 重名/歧义、T21 path_metrics、T22 BOM JSON）；`main.py --check` ALL PASS。
