# 契约变更记录（P1 · P2 · 2026-10-17 至今）

> 规则来源：《技术方案》§6.5 —— **只加不改**，破坏性变更必须 bump 主版本并全组同步。
> 当前 `core.CONTRACT_VERSION = "1.3.0"`。

## [1.3.0] 2026-10-18 · P1 回填 P2 的两项请求 + 动态增删 API

| 项 | 变更 | 影响面 | 兼容性 |
| --- | --- | --- | --- |
| `_add_edge` 存储精度（**R1**） | 去掉 `round(dist, 3)` / `round(t, 2)`，`Edge.distance_km` / `Edge.time_min` 存全精度 | 所有读到边权的下游；取整改由展示层（`Result`、`path_metrics`）负责 | ⚠️ 数值语义变化：同一份数据读出的边权不再被截断到 3/2 位 |
| 加载期几何自洽校验（**R2**） | 新增 `time_min ≥ distance_km / v_max × 60 − 1e-9`（`v_max` = 全网最大 `speed_kmh`），违反抛 `DataError`；`validate()` 同样执行，幂等 | 显式写了偏小 `time_min` 的数据文件会被拒绝 | ⚠️ 更严格：以前能加载的"时间过快"数据现在报错 |
| `Graph.add_station(station)` | 新增公开方法，返回 `Station` | P3/P4 可用于运行时建站 | ✅ 纯新增 |
| `Graph.add_edge(edge)` | 新增公开方法，走与加载相同的全部校验，返回新建的 `Edge` | P2/P3 可用于运行时加边 | ✅ 纯新增 |
| `Graph.remove_edge(u, v, line)` | 新增公开方法，返回删除条数（0/1） | 同上 | ✅ 纯新增 |
| `Graph.remove_station(sid)` | 新增公开方法，**级联删除**它的所有边，返回删掉的边数；删完检查无悬空边 | 同上 | ✅ 纯新增 |
| `Graph._rebuild_adj()` / `_log_mutation()` | 私有：前者按 `edges` 重建邻接表，后者把改动记进 `meta.mutation_log` | 内部 | ✅ 内部 |
| `core.CONTRACT_VERSION` | `1.2.0` → `1.3.0`（`1.2.0` 已被 P3/P4 的 `Result.lines` 变更占用，本项顺延） | 全组可见 | 次版本：有行为变化但无签名破坏 |

**变更理由**：
1. R1 —— 取整让 A\* 的欧几里得启发式 `h` 出现 ≤0.5% 的**微小高估**（实测 `S10→S11`：`h=3.0233` vs 存储最优 `3.02`），
   可采纳性只能"容差成立"；存全精度后 `h ≤ 真实代价` 严格成立，报告里的最优性证明不需要补丁。
   P2 的验收标准已满足：`python -m unittest tests.test_solver.TestOptimality -v` **5 条全过**。
2. R2 —— 显式 `time_min` 偏小时 A\* 会高估、可能返回非最优路径，且小数据测不出来，必须在加载期拒掉。
3. 动态增删 —— 任务书 P1-06 要求，且报告"支持动态增删"需要代码证据（`meta.mutation_log` + 单测 T12/T12b）。

**新增数据文件（P1-04 / P1-05）**：

| 文件 | 用途 | 规模 |
| --- | --- | --- |
| `data/tiny_hand.json` | P2 严格可采纳性断言（T14a）：边权精确可表示 | 3 站 / 3 边 |
| `data/edge_cases.json` | 边界：孤立站、99.5 km 长空档、0.5 km 超短边 | 5 站 / 3 边 |
| `data/metro_raw.csv` + `data/real_metro.json` | 真实规模回归与基准（`tools/import_metro.py` 生成） | **169 站 / 188 边 / 10 线 / 29 换乘站** |

**验证**：`python main.py --check` → ALL PASS；`python -m unittest tests.test_graph -v` → **16 条全过**；
`python -m unittest tests.test_solver.TestOptimality -v` → 5 条全过。

**⚠️ 需要 P2 同步的两处（P1 不越界改 P2 的文件）**：

| 位置 | 现状 | 建议改法 |
| --- | --- | --- |
| `tests/test_solver.py::test_t07_parallel_lines_prefer_fewer_switches`（约 149–150 行） | 断言 `2 * round(60 / 35, 2)`，注释说明"加载器把每条边时间取整到 2 位" | 改为 `2 * (60 / 35)`：R1 后不再有取整 |
| `tools/bench.py::main`（约 147 行） | `help="变异系数上限（%），超过则退出码 2"` 中的裸 `%` 在 Python 3.14 下触发 `ValueError: badly formed help string` | 写成 `（%%）` 转义 |

## [1.1.0] 2026-10-17 · P2 新增可选 `heuristic` 参数（向后兼容）

| 项 | 变更 | 影响面 | 兼容性 |
| --- | --- | --- | --- |
| `astar(g, start, goal, weight="time", heuristic=None)` | 新增可选参数，签名 `heuristic(g, sid, goal) -> float` | P3/P4 走 `solve()`，不受影响 | ✅ 向后兼容（默认 None 用内置 h） |
| `core.CONTRACT_VERSION` | 新增常量 `"1.1.0"` | 全组可见 | ✅ 纯新增 |
| `bfs_transfers` 内部 | 增加 `processed` 集合（0-1 BFS 标准去重） | 只影响 `expanded` 数字（变准），不改语义 | ✅ 结果不变 |
| `_heuristic(...)` | 增加可选 `vmax` 形参（A* 每次求解只算一次最大速度） | 私有函数 | ✅ 内部 |

**变更理由**：报告需要"曼哈顿 vs 欧几里得"的对比实验；单测需要注入**非可采纳** h 来证明测试有判别力（T15）。
用参数注入比 monkeypatch 干净，且不改 `Result`、不改 `solve()`、不改异常类型。

**验证**：`python main.py --check` 仍 ALL PASS；`python -m unittest discover -s tests -t .` 18 条全过。

## 待 P1 决策（数据精度，会影响"可采纳性"的严格性）

| 现象 | 证据 | 建议 |
| --- | --- | --- |
| 加载器把 `time_min` / `distance_km` 取整到 2/3 位小数，**向下误差 ≤0.005/边**，导致几何启发式可能出现 ≤0.5% 的微小高估 | 单测 T14b；实测 `S10→S11`：`h=3.0233` vs 存储最优 `3.02` | **存储保留全精度，显示层（`Result`）再取整**。这样 `h ≤ 真实代价` 严格成立，报告里的可采纳性证明不用加"取整容差"补丁 |
| 影响 | 目前 A\* 与 Dijkstra 在 180 个（点对×权重）上代价仍完全一致（T03/T04），但严格性上留了一个小口子 | 若 P1 同意，改动只在 `core/graph.py` 的 `_add_edge` 两行（P1 的文件，P2 不越界改） |

## [1.2.0] 2026-10-18 · Result 增加 `lines` + 三项健壮性修复

| 项 | 变更 | 影响面 | 兼容性 |
| --- | --- | --- | --- |
| `Result.lines` | 新增字段：每跳所用线路序列（`len(path)-1`） | P3 画线/标注应改用它；P4 只在统稿说明里提 | ✅ 纯新增 |
| `core/graph.validate()` | 新增**站名查重**（重名抛 `DataError`） | P1 数据加载；`main.resolve` 歧义不再静默 | ⚠️ 以前能加载的重名数据现在会被拒 |
| `solver.bfs_transfers` | 不再校验无关的 `weight`（改用 `_check_stations`） | 无行为变化 | ✅ |
| `Graph.path_metrics()` | 同站换乘段按 0 距离/0 时间跳过（不再抛异常） | 展示层累计 | ✅ |
| `main.resolve()` | 同名站点命中多个时**报歧义**并列出候选 id | CLI/界面选点 | ⚠️ 重名数据会得到明确错误 |

**验证**：单测 19→**23**（T19 lines、T20 重名/歧义、T21 path_metrics、T22 BOM JSON）；`main.py --check` ALL PASS。
