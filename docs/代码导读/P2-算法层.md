## 2. 阅读顺序（按行号）

1. `core/solver.py:34` `Result`——字段 `path / lines / distance_km / time_min / transfers / expanded / events`，界面只读它。
2. `:78` `_heuristic()`——distance 用欧氏距离；time 用 `欧氏 / v_max × 60`；可采纳 + 一致。
3. `:90` `analyze_path()`——沿路径做 DP，选“换乘最少、再按时间”的线路组合，并返回每跳线路 `lines`。
4. `:135` `dijkstra()`——`(dist, sid)` 做 tie-break，扩展数 = 出堆且首访。
5. `:172` `astar()`——`(f, g, sid)`；`heuristic` 可注入（测试用它验证不可采纳会被抓）。
6. `:220` `bfs_transfers()`——0-1 BFS，状态是 `(station, line)`；同线代价 0（appendleft），换线 +1（append），`processed` 去重。
7. `:310` `pick_connected_pair()`、`:342` `solve()`——对外入口与自动选点。
8. `tests/test_solver.py`：T01–T23；重点看 T03/T04（A* 与 Dijkstra 同优）、T14/T15（可采纳性红绿测试）、T16/T19（换乘与 lines 一致性）。

## 3. 核心口径（必须能讲清）

- **扩展数**：节点出堆且第一次访问记 1；`len(events) == expanded`。
- **BFS 的单位是状态**不是站点，所以它扩展数看起来更多。
- **tie-break**：Dijkstra `(dist, sid)`、A* `(f, g, sid)`、BFS `sorted(lines)`——保证结果确定。
- **A* 的收益由 h 紧度决定**：distance 约省 50%，time 因 `v_max` 与线路速度差只省 9–22%。

## 4. 五个自测问题

1. 为什么 time 权重的 `h` 要除以全网最大速度，而不是平均速度？
2. 0-1 BFS 为什么同线用 `appendleft`、换线用 `append`？状态里为什么必须带线路？
3. A* 的 `h` 不可采纳时会出现什么？测试 T15 怎么把它抓出来？
4. `Result.lines` 与 `transfers` 的关系？为什么画线必须用 `lines`？
5. `expanded` 和“访问过的站点数”有什么区别？

## 7. 坑

- 单次 µs 级计时噪声很大：必须批量 + 多轮中位数，CV 闸门看中位。
- 不要为了让数字好看去取整边权；契约 1.3.0 已全精度。
- `bfs_transfers` 忽略 `weight`，这是定义不是 bug。
