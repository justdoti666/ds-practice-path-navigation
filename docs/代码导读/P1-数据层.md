# P1 · 数据层代码导读

> 你负责：**把数据变成可信的 Graph**。加载、校验、精度、几何自洽、动态增删、真实数据生成。
> 关键文件：`core/graph.py`、`data/`、`tools/import_metro.py`、`tools/gen_stress_data.py`、`tools/data_stats.py`、`tests/test_graph.py`

## 1. 先跑通

```powershell
python main.py --data data\demo_city.json
python -m unittest tests.test_graph -v      # 16 条数据层测试
python main.py --check                       # 自检里也会验数据
```

## 2. 阅读顺序（按行号）

1. `core/graph.py:27` `Station`、`:39` `Edge`、`:51` `Graph`——只看字段和 `neighbors/edge_between/lines_of_station/bbox`。
2. `:105` `validate()`——**整层的核心**：站数、站名唯一、边端点存在、距离/时间为正、线路已定义、几何自洽（时间不能快过全网最高速）。
3. `:246` `load_json()`、`:272` `load_txt()`、`:315` `load_graph()`——后缀分发；JSON 用 `utf-8-sig` 兼容 BOM。
4. `:145` `add_station`、`:151` `add_edge`、`:157` `remove_edge`、`:169` `remove_station`——运行时增删；删站会级联删边并重建邻接表。
5. `data/demo_city.json`（10 站）→ `data/real_metro.json`（169 站）→ `tools/import_metro.py`（线性近似坐标的生成器）。
6. `tests/test_graph.py`：T01–T15 + T12/T12b，逐条对照实现。

## 3. 核心链路

```
load_graph(path)
  ├─ .json → load_json → _add_station/_add_line/_add_edge → _finish() → validate()
  └─ .txt  → load_txt  → 同上
```

必须能回答：为什么边权要**存全精度**？因为 P2 的 A* 用坐标算启发式，取整会让 `h` 轻微高估、可采纳性只能“容差成立”。展示层（`Result`/`path_metrics`）再取整。

## 4. 五个自测问题

1. `validate()` 里的 `time_min ≥ distance_km / v_max × 60` 是怎么来的？违反它为什么会影响 A*？
2. 站名重复为什么要在加载期拒绝？`main.resolve()` 重名时会怎样？
3. `remove_station()` 为什么要重建 `adj`？不重建会出什么 bug？
4. JSON 和 TXT 怎么保证“同一张图”？自检第 1 组在做什么？
5. 为什么 `data/real_metro.json` 的坐标只是“线性近似”，不能当真实地理坐标？

## 5. 小练习

- 给 `demo_city.json` 加一个站 + 一条边，跑 `tests.test_graph` 和 `main.py --check`，确认站数/边数变化。
- 把某条边的 `time_min` 手工改小到违反几何自洽，看加载报错信息。
- 用 `tools/import_metro.py --check` 重新生成一版，确认加载通过。

## 6. 验收命令

```powershell

python tools/import_metro.py --check
python tools/data_stats.py
```

## 7. 坑

- 读 JSON 用 `utf-8-sig`（Windows 记事本会写 BOM）。
- 站名必须唯一；边 key 是 `(min(u,v), max(u,v), line)`。
- `edge_between()` 返回**列表**（平行线路可能多条），不要改成单条——P2 的 `analyze_path` 依赖列表。
