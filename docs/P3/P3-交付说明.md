## 2. 任务逐条对照

### P3-01 主窗骨架（2 点）

* 1180×720，最小尺寸与设计尺寸相同（窗口不允许再缩小，避免控件被裁切）；
  左栏 336 px 固定宽，右侧 800 px 自适应，放大时画布与结果区按权重伸展。
* 控件树：起终点下拉、交换、点选模式按钮、算法下拉、权重单选、搜索/对比/清除/取消、
  状态徽标 + 提示、运行日志、画布、5 张指标卡、途经站点清单、三算法对比表、
  动画速度与重播、重新加载。
* 状态变量全部集中在 `Controller`（`state / start_id / end_id / algorithm / weight /
  result / last_error`），控件只读不写。
* 证据：`docs/截图/01-主界面.png`；控件无重叠/裁切（固定 96 DPI 排版 + `minsize`）。

### P3-02 起终点选择（2 点）

* 下拉框统一文案 `站名（ID）`，解析用 `parse_station_label()`（`rsplit("（", 1)`，
  兼容半角括号）。
* 点选联动：`bind_click → _on_canvas_click → _apply_pick`，写入对应下拉框并即时画
  `起/终` 标记；点空白处 `CanvasView` 不回调，因此不会误选。
* 模式独立：`pick_mode ∈ {None,"start","end"}`，两个按钮互斥高亮；选完一次自动退出
  点选模式，避免下一次点击意外改选。
* 无模式时也支持"先点起点、后点终点"的直接点选；两个都选好后再点会提示先按按钮改选。
* 证据：`docs/截图/02-点选交互.png`；日志里能看到"点选起点/点选终点"记录。

### P3-03 搜索状态机（2 点）

`SearchState`：`IDLE → READY → COMPUTING → RESULT / ERROR`，另有 `cancel()` 回到 READY。

* `begin_search()` 在 `COMPUTING` 状态下**幂等**：连点 5 次返回同一个 token、只跑一次
  solver（`test_repeated_clicks_only_solve_once` 断言 `solve_calls == 1`）。
* solver 在后台线程执行，结果经 `queue.Queue` + `after(40ms)` 回到主线程，
  界面不卡、也不会跨线程碰 Tk。
* 计算中禁用搜索/对比/清除/交换/点选与三个下拉；`取消` 按钮仅此时可用。
* token 机制丢弃迟到结果：取消后旧 token 的 `apply()` 不再落地（有用例覆盖）。
* 未选点、空图、起终点相同都在 `begin_search()` 前校验，不进入计算。
* 动画期间同样禁用按钮（`_animating` + `_set_buttons_busy`）。

### P3-04 结果面板（2 点）

* 指标卡：`km / min / 换乘 / 扩展 / 耗时`，搜索后立刻刷新。
* 途经站点：逐站列出 `序号 + 站名 + ID`，并逐段附 `线路 · 里程 · 时间`；超过可视高度
  自动可滚动（Text + Scrollbar）。
* 三算法对比：`ttk.Treeview` 三行（Dijkstra / A* / BFS），最优行浅绿底（并列最优同时高亮）；
  "校验"列显示 `✓ 一致 / × 不一致 / — 无基准`。
* 数值来源：界面现场调用 `core.solver.solve()`，`bench.csv` 也由同一 solver 生成
  （`tools/make_bench.py`），`--check` 每次重算并逐项比对，杜绝手抄。
* 证据：`docs/截图/03-搜索结果.png`、`04-三算法对比.png`。

## 4. 接口契约

### 4.1 我调用别人

```python
from core.graph import load_graph          # P1
graph = load_graph(data_dir)               # data_dir=None 时用 data/
graph.stations["S02"].name                 # Station(id, name, x, y, lines)
graph.neighbors("S02")                     # list[Edge(u, v, line, km, minutes)]
graph.edge_between("S01", "S02")           # 界面显示线路名用
graph.iter_edges()                         # 画布去重边
graph.is_empty / len(graph)

from core import solver                    # P2
result = solver.solve(graph, s, t, "dijkstra", "time")
# Result: algorithm/found/path/distance_km/time_min/transfers/expanded/elapsed_ms/events
# path 是站点 id 列表（含起终点）；events 供动画扩展，界面不依赖它
```

* 任何数据/算法异常都会被 `Controller.perform()` 包成 `DataError` 弹窗，**不会崩**；
  所以 P2 只要在数据不对时正常 `raise` 即可。
* P2 若很慢，`Controller.compare()` 目前是同步调用三行，会短暂卡住 UI；
  接真算法时建议按 `_run_async` 的写法改成后台线程（改动只在 `_on_compare`）。

### 4.2 我给 P4

```python
view = CanvasView(parent_frame, graph)      # 必须提供 .master / .grid / .destroy
view.bind_click(callback)                   # callback(sid)；点空白不回调
view.show_path(result)                      # 静态高亮
view.animate(result, speed_level=1, on_done=None)   # on_done 可选
view.reset()                                # 清高亮/选中/动画
```

可选（没有也能跑）：

```python
view.show_selection(start_sid, end_sid)          # 起终点标记，缺失时只靠下拉框
view.animation_duration_ms(result, speed_level)  # 缺失时界面按 1.2 s 兜底
view.station_screen_pos(sid)                     # 截图脚本点操作用，测试替身可返回 None
```

`animate()` 的 `on_done` 若 P4 不接受，界面会捕获 `TypeError` 并用固定时长解锁按钮，
不会报错——但建议 P4 保留，动画结束时机更准。
