## 3.1 统一骨架：一张表说清三种算法的差别

三种搜索都建立在同一套"松弛 + 优先队列"骨架上，差别只在**取谁的次序**与**状态是什么**：

| 算法 | 状态 | 取出次序 | 松弛条件 | 终止条件 |
| --- | --- | --- | --- | --- |
| Dijkstra | 站点 | 当前**已走代价**最小 | `dist[u]+w < dist[v]` | 目标被弹出 |
| A\* | 站点 | `f = g + h` 最小 | 同上（`g` 为已走代价） | 目标被弹出 |
| 0-1 BFS（最少换乘） | `(站点, 线路)` | 队列顺序（0 代价入队首、1 代价入队尾） | `cost[u]+c < cost[v]`，`c ∈ {0,1}` | 目标状态被弹出 |

实现上公共部分抽象为"优先队列 + `prev` 回溯 + 指标统计"，三种算法各自只写 30–40 行核心循环，
`Result` 统一记录路径、距离、时间、换乘数、扩展节点数与耗时——这保证了界面层与算法层解耦（见第 4 章）。

## 3.2 最快路径：Dijkstra 与松弛（图 3-1）

Dijkstra 的正确性依赖非负权重：本项目的边权取"距离（km）"或"时间（min）"，加载阶段已校验为正数，
因此满足前提。核心是**松弛（Relaxation）**：

```
dist[s] = 0；其余 dist = +∞
堆 ← {(0, s)}
while 堆非空:
    (d, u) ← 弹出最小者
    if u 已出堆: continue          # 懒惰删除：跳过过期条目
    if u == goal: break
    for e = (u, v, w) in 邻接表[u]:
        if d + w < dist[v]:
            dist[v] = d + w;  prev[v] = u;  堆 ← {(dist[v], v)}
```

**为什么用堆**：每轮"取最小"若线性扫描为 `O(V)`，总计 `O(V²)`；二叉堆把单次取最小降到 `O(log V)`，
总体 `O((V+E)logV)`，在本项目"站点上千、每站 2–4 条边"的稀疏图上优势明显。

**双权重**：同一张图，权重换成 `distance_km` 就得到"最短距离"路径。示例城市里
"大学城 → 机场"最快为 15.98 km / 17.88 min（2 次换乘），最短为 3.64 km / 21.84 min（0 次换乘），
**两者不是同一条路径**——这正是"多准则"要展示的现象。

## 3.3 最少换乘：为什么必须是 0-1 BFS（图 3-3）

"最少换乘"最容易被写错成"对站点做普通 BFS"。那样得到的是**最少站数**，与换乘次数无关：
一条直达慢线（20 站）与一条换乘 1 次快线（5 站），普通 BFS 会选前者。

正确建模是把**线路也纳入状态**：状态 `(站点, 当前线路)`。

- 沿同一条线路走到相邻站：换乘数不变，代价 **0**；
- 在当前站改乘另一条线路：换乘数 +1，代价 **1**。

于是问题变成"边权只有 0 和 1 的最短路"，用**双端队列**求解即可：代价 0 的分支压**队首**、代价 1 的压**队尾**。
队列的弹出顺序始终按代价非降，因此**第一次弹出目标状态时的代价就是最小换乘数**。

回溯得到 `(站点, 线路)` 序列后，把"同站换线"压平成一次站点，得到最终站点路径。
复杂度：状态数 `V·L`（`L` 为单站最大线路数），每条边在每个线路层至多松弛一次，
总时间 `O(V·L + E)`，空间 `O(V·L)`。

> 注意 `Result.expanded` 在 BFS 里统计的是**状态数**，与另外两个算法（站点数）口径不同，
> 对比实验的表注必须写明，否则会被误读成"BFS 扩展得更多、更慢"。

## 3.4 A\*：启发式的可采纳性与紧度（图 3-2）

A\* 把"已走代价"和"到终点的估计"相加：`f(n) = g(n) + h(n)`，每次扩展 `f` 最小者。

**可采纳（admissible）**：`h(n) ≤ n 到终点的真实最小代价`。只要可采纳，A\* 第一次弹出目标时即为最优解。
本项目的两套 `h`：

| 权重 | 启发函数 | 为什么可采纳 |
| --- | --- | --- |
| 距离 | `h(n) = ‖P_n − P_goal‖`（欧氏直线距离） | 任何绕行路径长度 ≥ 直线距离 |
| 时间 | `h(n) = ‖P_n − P_goal‖ / v_max × 60` | 用时 = 距离 / 线路速度，线路速度 ≤ 全网最大速度 `v_max`，故真实用时 ≥ 上式 |

**一致性（consistency）**：两套 `h` 还满足 `h(u) ≤ w(u,v) + h(v)`（因为 `w ≥ 欧氏距离` 且 `v_line ≤ v_max`），
所以每个节点只需扩展一次，无需重新打开已关闭节点。这一点由单测 T03/T04 的"全点对与 Dijkstra 同代价"守住。

**紧度决定加速比**：`h` 越接近真实代价，扩展越少。实验结果正好印证：

- `distance` 权重上，`h` 几乎等于网格上的真实剩余代价 ⇒ A\* 扩展数比 Dijkstra **少约 50%**（240 站：84.7 vs 168.3）；
- `time` 权重上，`h` 用了全网最大速度 160 km/h，而多数线路只有 40 km/h，估计值系统性偏小 ⇒ 只省 **9%–22%**。

这也解释了任务书 Tips 里"换不同 `h` 观察搜索节点数"的意义：
把 `h` 换成曼哈顿距离会**高估**（本书单测 T15 用注入方式复现：结果从最优 10.00 min 退化到 10.75 min），
提示"可采纳"不是形式要求，而是最优性的前提。

## 3.5 复杂度分析（表 3-1）

| 算法 | 时间 | 空间 | 关键次数 |
| --- | --- | --- | --- |
| Dijkstra | `O((V+E) log V)` | `O(V+E)` | 每条边至多一次松弛；每点一次出堆 |
| 0-1 BFS | `O(V·L + E)` | `O(V·L)` | 每个状态一次入/出队；每条边每层一次 |
| A\* | 最坏 `O(E log V)` | `O(V+E)` | 扩展数 ≤ Dijkstra（同 h 下），实际由 h 紧度决定 |

符号：`V` 站点数、`E` 边数、`L` 单站最大线路数、`h` 启发函数。
复杂度必须写成"每次操作 × 调用次数"的形式；只写 `O(n)` 无法解释为什么 A\* 与 Dijkstra 在实测里差一半。

## 3.6 实测与讨论（表 3-2）

测试环境：Python 3.12.14，共享桌面；计时采用"批量执行 + 7 轮中位数"，抖动用变异系数控制（中位 8.25%）。

| 数据集（站点/边） | Dijkstra 扩展 | A\* 扩展 | Dijkstra 中位耗时 | A\* 中位耗时 | A\* 省扩展 |
| --- | --- | --- | --- | --- | --- |
| 示例城市（10 / 10） | 7.3 | 4.3 | 0.0068 ms | 0.0081 ms | 41% |
| grid-16（16 / 25） | 11.0 | 9.5 | 0.0155 ms | 0.0189 ms | 14% |
| grid-30（30 / 49） | 25.0 | 17.3 | 0.0287 ms | 0.0370 ms | 31% |
| grid-60（60 / 109） | 43.0 | 33.3 | 0.0528 ms | 0.0762 ms | 23% |
| grid-240（240 / 465） | 168.3 | 84.7 | 0.1466 ms | 0.1244 ms | **50%** |

（均为 `distance` 权重；完整数据含 `time` 权重与 BFS，见 `docs/bench.md`。）

三点讨论：

1. **扩展节点数**是算法层面的指标，**耗时**是实现层面的指标，两者趋势不完全一致：
   小图上 A\* 的常数开销（每步多算一次 `h`）可能盖过扩展数的收益，直到 240 站才显出优势。
   报告里不能只贴耗时就说"A\* 更快"，必须同时给扩展数。
2. **A\* 的收益有上限**：当 `h` 很松（如 time 权重）时，A\* 退化为"带常数开销的 Dijkstra"，
   这正是"可采纳但不紧"的代价。
3. **BFS 不可替代**：它优化的是换乘次数，不是距离或时间。在 grid-240 上 BFS 平均换乘 0.67，
   而 `Dijkstra(time)` 的平均换乘为 5.67——若只看"最快"，用户会被安排 5 次换乘。
