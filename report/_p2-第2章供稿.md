## 2.x 辅助结构一：优先队列（二叉堆）在 Dijkstra 中的作用

Dijkstra 每轮要做两件事：**取当前距离最小的节点**、**更新邻居的距离**。前者若用数组线性扫描，
单次 `O(V)`，`V` 轮下来是 `O(V²)`；换成二叉堆后单次 `O(log V)`，总复杂度降到 `O((V+E)log V)`。

工程上还有两个细节值得写进报告：

1. **懒惰删除**：Python 的 `heapq` 不提供 `decrease-key`。我们的做法是"允许同一节点在堆里出现多次，
   弹出时若已处理过就跳过"（`if u in done: continue`）。这使堆内条目数最多 `O(E)`，复杂度不变、实现更简单。
2. **确定性**：堆键写成 `(dist, 站点id)`，同距离时按 id 升序出堆。否则 Python 比较到第二元素时若再次并列，
   结果会依赖插入顺序，实验不可复现（单测 T13 专门固化这一点）。

A\* 复用同一个堆结构，只是把键换成 `(f, g, 站点id)`；0-1 BFS 不用堆，改用 `collections.deque`
（代价 0 入队首、代价 1 入队尾），因为它只需要区分两种代价。

## 2.y 辅助结构二：为什么"最少换乘"需要 `(站点, 线路)` 状态空间

若把每个站点当作一个节点、一次相邻移动当作一条边，那么对站点做 BFS 得到的是**最少站数**，
而题目要的是**最少换乘**。两者不等价：一条 20 站的直达线只需 0 次换乘，而一条 5 站但换 1 次的快线对
"最少换乘"不利。

正确做法是把线路信息放进状态：状态 = `(站点, 当前线路)`。

- 同线路相邻站之间移动：换乘数不变（代价 0）；
- 在同一站点切换到另一条线路：换乘数 +1（代价 1）。

于是"最少换乘"等价于边权为 `{0,1}` 的最短路，用双端队列（0-1 BFS）即可在 `O(V·L + E)` 内解决，
其中 `L` 是单站最大线路数。代价是状态空间从 `V` 扩大到 `V·L`——这是"用空间换语义正确"的典型取舍，
也应写进报告的"数据结构选型理由"里。

> 备注：`Result.expanded` 在 BFS 中统计的是**状态数**，与 Dijkstra/A\* 的站点数口径不同，表格必须加注。
